# 统一更新方案

## 推荐结构：一个本地配置外壳 + 两类远程内容

Clash 中只保留一个正在运行的配置文件，但配置文件内部同时管理：

1. **远程订阅**：通过 `proxy-providers.订阅节点` 获取节点。
2. **远程分流规则**：通过 `rule-providers` 从本仓库 Raw 地址获取规则。

本仓库的 `Clash/配置模板.yaml` 已按此结构编写。真实订阅地址只填写在本机，不能提交到公开 GitHub。

服务商的完整配置链接可以作为“代理提供商”地址使用：Clash 只读取其中的节点列表，不会采用其中的 `rules`、`dns` 或 `proxy-groups`。关键是不要把该链接直接作为活动配置。

## 一次性设置

1. 在 Clash 中导入 `Clash/配置模板.yaml`，或在当前配置中加入同样的 `proxy-providers` 和 `rule-providers` 配置。这个步骤只做一次。
2. 将服务商的完整订阅地址填写到“代理提供商”，而不是作为活动配置 URL。真实订阅地址填写到：

   ```yaml
   proxy-providers:
     订阅节点:
       url: "这里填写真实订阅链接"
   ```

3. 激活这一个配置，并确认策略组能够读取“订阅节点”。
4. 删除或停用旧的重复配置。

之后不需要反复导入本地文件。

## 日常更新

- **更新节点订阅**：在 Clash 的配置/订阅页面点击“更新”或“更新代理提供商”。
- **更新分流规则**：在规则提供商页面点击“更新”；模板中的 `interval: 86400` 也会每天自动更新。
- **更新仓库后**：只需更新规则提供商，不需要重新导入配置。

规则更新地址固定在模板中，例如：

```text
https://raw.githubusercontent.com/Graffiti-yH/clash-qx-config/main/规则/Clash/中国大陆直连.list
```

Bilibili 已合并到“中国大陆直连”，不再单独占用一个规则提供商。

## 关于当前正在使用的本地配置

如果当前配置是服务商直接下发的“完整配置”，它通常会同时带有服务商自己的分流规则；点击订阅更新时还可能覆盖本地修改。此时有两个选择：

- **推荐**：一次性改用本仓库模板作为配置外壳，把服务商链接放进 `proxy-providers`，让节点和分流规则分别远程更新；服务商分流规则不会生效。
- **保留现有配置**：在该配置中一次性加入本仓库的远程规则提供商；但如果服务商更新会覆盖整个配置，规则仍可能被覆盖。

公开 GitHub 不能放真实订阅链接。若要做到“一个远程 URL 同时生成节点和分流配置”，需要订阅服务商或自建服务支持服务端模板合并；不能把含密码的订阅 URL 写入公开仓库。使用本模板时虽然配置外壳在本机，但节点和规则都能在 Clash 内更新，无需反复本地导入。
